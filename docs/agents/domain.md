# Domain docs

This repo has one domain context. Before exploring or changing domain behavior, read the vocabulary in `CONTEXT.md` and the relevant decisions in `docs/adr/`. Use those terms in specs, tickets, tests, and code.

If a root `GLOSSARY.md` is created later, read it too. Create it only when a new term needs a definition. If a proposed change conflicts with an ADR, call out the conflict rather than silently overriding the decision.
